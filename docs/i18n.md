# Translations (`vue-i18n`)

For the general "all text goes through translations" rule and the `c-component-name.keyName` key
namespacing convention, see the [Translations section](../README.md#translations) of the README. This
page covers how the setup in `src/setup/i18n.ts` actually works.

## Setup

`src/setup/i18n.ts` creates and exports the `vue-i18n` instance (`legacy: true`, so both the Options
API `$t()` and the Composition API `useI18n()` styles work). It's registered as a plugin in
`src/setup/plugins.ts` — first in the list, because plugin registration order must keep i18n before the
BEM-related setup.

- `I18N_FALLBACK = 'en'` and `I18N_LOCALES = ['en', 'de']` are the two supported locales.
- `PAGE_LANG` reads `document.documentElement.lang` — another instance of the "server owns the page"
  pattern: the active locale defaults to whatever language the server template already set on `<html
lang="...">`, rather than Vue maintaining its own locale state independently.
- `en.json` (from `src/translations/`) is imported eagerly and used as the fallback message bundle
  (`I18N_FALLBACK_MESSAGES`); it's also always loaded as `fallbackLocale`.
- A `missing` handler logs an error to the console whenever a translation key isn't found for the
  active locale.
- `datetimeFormats` are configured for `'long'` month and weekday names, registered under both `en` and
  the page's own locale.
- A `decimal` (2 fraction digits) and `percent` (no grouping) `numberFormats` entry are configured for
  `en`.

## Translation files and lazy loading

Translation files live in `src/translations/` — one JSON file per locale (`en.json`, `de.json`).
`en.json` ships eagerly as the fallback bundle; any other locale is loaded on demand:

- `i18nLoadMessages(locale)` dynamically `import()`s `../translations/${locale}.json` the first time a
  locale is needed, then registers it via `i18n.global.setLocaleMessage(locale, ...)` and caches it on
  the `i18n` instance (a locale already present in `i18n.global.messages` is not re-fetched).
- `i18nSetLocale(locale)` is the entry point to switch locales: it falls back to `I18N_FALLBACK` if
  `locale` isn't in `I18N_LOCALES`, does nothing if it's already the active locale, otherwise calls
  `i18nLoadMessages`, updates the shared Axios instance's `locale` header (see
  [state-and-data-flow.md](./state-and-data-flow.md#locale-header)), and sets `i18n.global.locale`.
  `i18n.ts` calls `i18nSetLocale(PAGE_LANG || I18N_FALLBACK)` once at module load, so the app starts in
  the page's own language.

Outside a component's template (a `.ts` file, a store, a plugin), import the `i18n` instance directly
from `@/setup/i18n` rather than trying to inject `$t`.

## Styleguide-only translations

`src/styleguide/translations.json` holds strings used only by the dev styleguide (see
[styleguide.md](./styleguide.md)) — labels for the styleguide UI itself, or sample copy for demo
widgets. `i18n.ts` merges this file's entries into `I18N_FALLBACK_MESSAGES` (and, per-locale, into
whatever a lazily loaded locale file resolves to) **only when `import.meta.env.MODE !== 'production'`**
— so in a production build these keys are never registered, and a production bundle's translation
payload is exactly the project's real strings.
